# sKole Mobile

A React Native + Expo application for the sKole mobile experience. This project lives in the `mobile/` folder and is intentionally kept separate from the web app in `skole/`.

## Overview

This app is built with:

- Expo SDK 57
- Expo Router for file-based navigation
- React Native
- TypeScript
- pnpm-based dependency management in a monorepo workspace context
- a shared mobile design system centered on the app theme constants and native-safe UI patterns

The app entry is configured via `app.json`, and navigation is handled from the `app/` directory using Expo Router.

## Project architecture

### Core stack

- **Expo**: manages the React Native toolchain, Metro, native builds, and app configuration
- **Expo Router**: powers the app navigation and screens through the `app/` folder
- **TypeScript**: enforces safer component and utility development
- **React Native**: provides the underlying mobile UI runtime
- **pnpm workspace integration**: keeps the app package aligned with the broader monorepo layout while allowing mobile-specific dependencies and scripts

### Main folders

```text
mobile/
├── app/                  # Expo Router screens and layouts
├── app.json              # Expo app metadata and native/plugin config
├── assets/               # Images, fonts, and splash assets
├── components/           # Shared UI and reusable React Native helpers
├── constants/            # Theme and color tokens
├── docs/                 # Product and implementation reference docs
├── services/             # API/service helpers
├── package.json          # Expo package manifest and scripts
├── tsconfig.json         # TypeScript config
├── pnpm-lock.yaml        # pnpm lockfile
├── eslint.config.js      # ESLint setup
├── README.md             # Developer setup and workflow guide
├── android/              # Generated by Expo/CNG; do not edit by hand
├── ios/                  # Generated by Expo/CNG; do not edit by hand
└── .env                  # Local environment values for Expo public vars
```

> The actual route files in this repo are in `app/`, not a separate `src/app/` directory, so follow the live project structure rather than a generic template.

## Prerequisites

Before you start, make sure you have:

- **Node.js LTS** installed (recommended baseline: Node 20 LTS for Expo SDK 57 compatibility)
- **pnpm** installed and available on your PATH
- A working Android emulator, or a physical Android device connected over USB / ADB
- Access to the backend API that the mobile app calls

## Local environment setup

### 1. Install dependencies

From the project root or the `mobile/` package directory, install dependencies with pnpm:

```bash
cd mobile
pnpm install
```

If the repository is opened as a pnpm workspace, install at the workspace root when the workspace is configured to manage all packages together. In this app, keep package-specific commands targeted to `mobile/` when working on the Expo app itself.

### 2. Do not use package manager shortcuts for Expo packages

For Expo and React Native dependencies, prefer the Expo toolchain:

```bash
cd mobile
npx expo install <package-name>
```

This is the correct pattern for Expo-managed packages and avoids incompatible versions.

### 3. Create a local environment file

Create a `.env` file inside `mobile/`:

```env
EXPO_PUBLIC_API_URL=http://192.168.1.25:3000
```

Use your local machine or local network IP instead of `localhost` when testing with a physical Android device. `localhost` only works when the Android emulator is running on the same machine, not when using a real device on the same Wi-Fi network.

## Environment variables

The app resolves its API base URL from `EXPO_PUBLIC_API_URL`.

### Required variables

```env
EXPO_PUBLIC_API_URL=http://<your-local-ip>:<port>
```

### Physical Android testing

For a real Android device on the same network:

1. Find your machine’s LAN IP, for example `192.168.1.25`
2. Start the backend on that same machine or network-accessible host
3. Set:

```env
EXPO_PUBLIC_API_URL=http://192.168.1.25:3000
```

4. Restart the Metro server after the change

> Do not hardcode production URLs or store secrets in public Expo variables. `EXPO_PUBLIC_*` values are exposed to the client app.

## Running the app

### Start Metro

```bash
cd mobile
npx expo start
```

This starts the Metro bundler. From there you can:

- open the app in an Android emulator
- run on a connected physical device
- use Expo Dev Tools / QR flow if needed

### Run Android locally

```bash
cd mobile
npx expo run:android
```

This builds and launches the Android app using the local native project.

### Run the web app

```bash
cd mobile
npx expo start --web
```

## Continuous Native Generation (CNG) rules

This project follows the Expo CNG model:

- **Do not manually edit** `android/` or `ios/`
- **Do not hand-write native project changes** unless explicitly required by a native config workflow
- Configure behavior via `app.json` and Expo config plugins instead
- Let Expo generate the native directories when necessary, rather than maintaining them by hand

### Important rule

If you need a native behavior change, update the Expo config in `app.json` and any plugin configuration, then regenerate or rebuild the app using Expo commands.

> `android/` and `ios/` are generated artifacts, not the source of truth for mobile feature work.

## Development notes

### Navigation and screens

The app uses Expo Router and places screens under `app/`. Keep route logic in route files and move reusable UI logic into `components/`, `constants/`, and `services/`.

### Design and UX

Use the existing mobile theme constants rather than ad-hoc hardcoded values where possible. The app is designed around native mobile ergonomics, spacing, safe areas, touch input, and Android responsiveness.

### API integration

Use the app’s service layer and fetch from the backend through `EXPO_PUBLIC_API_URL`. Keep endpoint configuration centralized and avoid hardcoded backend URLs in component code.

## Definition of done

Before considering work complete:

- the app builds or runs in the expected local environment
- TypeScript and lint checks pass
- environment variables are set correctly
- API URLs use the local network IP for physical Android testing
- no manual edits were made to generated native directories

## Notes for contributors

This repository keeps the web and mobile experiences separate, with mobile as the implementation-focused workspace. When making mobile changes, stay inside `mobile/` and use the app’s current Expo/React Native conventions rather than web patterns copied directly into native code.
